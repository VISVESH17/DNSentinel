# DNSentinel — API Reference

Base URL (local dev): `http://localhost:8000`
Interactive docs (auto-generated by FastAPI): `http://localhost:8000/docs`

## DNS

### `POST /api/dns/check`
The core decision endpoint. Runs a domain through threat-intel matching,
ML scoring and the risk engine.

Request body:
```json
{ "domain": "malware-drop-93827.xyz", "client_ip": "192.168.1.12", "qtype": "A" }
```

Response:
```json
{
  "domain": "malware-drop-93827.xyz",
  "action": "BLOCK",
  "classification": "MALICIOUS",
  "risk_score": 87.0,
  "resolved_ip": "10.10.10.10",
  "latency_ms": 8.33,
  "reasons": [
    "Threat-intel match (confidence=95) +57",
    "DGA/ML probability=1.00 +20",
    "High entropy / lexical anomaly +10"
  ]
}
```

### `GET /api/dns/history?limit=50`
Returns the most recent DNS queries, most recent first.

## Threat Intelligence

### `POST /api/threat/feeds/sync`
Loads all CSV feeds under `/data` into the `threat_indicators` table.
Idempotent — safe to call repeatedly.

### `GET /api/threat/indicators?limit=100`
Lists currently synced threat indicators.

### `GET /api/threat/domain/{domain}`
Looks up whether a specific domain is a known threat indicator.

## Dashboard / Stats

### `GET /api/stats`
Overview counters: total queries, blocked/alerted/monitored/allowed,
threat indicator count, open alerts, average latency, detections by type.

### `GET /api/stats/timeline?hours=24`
Query counts bucketed by hour, split by action (ALLOW/MONITOR/ALERT/BLOCK).

### `GET /api/stats/top-domains?limit=10`
Most frequently blocked domains.

### `GET /api/stats/top-clients?limit=10`
Clients (by IP) generating the most DNS queries.

### `POST /api/threat/feeds/sync-stix` 🔒 admin/analyst
Parses `data/stix_sample_bundle.json` (a real STIX 2.x bundle) and
ingests its `indicator` objects into the threat_indicators table.

### `GET /api/threat/sources`
Lists configured feed sources (CSV feeds + the placeholder TAXII entry).

## Authentication

### `POST /api/auth/login`
Form-encoded (`username`, `password`). Returns a JWT bearer token.

Demo accounts:

| Username | Password | Role |
|---|---|---|
| `admin` | `admin123` | admin |
| `analyst` | `analyst123` | analyst |
| `viewer` | `viewer123` | viewer |

```bash
curl -X POST http://localhost:8000/api/auth/login \
  -d "username=analyst&password=analyst123"
```

Send the returned token as `Authorization: Bearer <token>` on protected
endpoints (marked 🔒 below).

### `GET /api/auth/me` 🔒 any role
Returns the current user's username and role.

## PCAP / Passive Investigation

### `POST /api/pcap/upload` 🔒 admin/analyst
Multipart upload of a Zeek `dns.log` file (`.log`/`.txt`, max 5MB).
Runs the DNS-tunnelling detector over aggregated sessions and returns
a summary. Try it with the included sample:

```bash
curl -X POST http://localhost:8000/api/pcap/upload \
  -H "Authorization: Bearer <token>" \
  -F "file=@data/sample_zeek_dns.log"
```

### `GET /api/pcap/{result_id}/results` 🔒 any role
Retrieves a previously uploaded analysis by its ID.

### `GET /api/pcap/history` 🔒 any role
Lists all PCAP analyses run this session.

## Alerts & Investigation

### `GET /api/alerts?status=open&limit=100` 🔒 any role
Lists alerts, optionally filtered by status
(`open`/`investigating`/`resolved`/`false_positive`).

### `GET /api/alerts/{id}` 🔒 any role
Fetch a single alert.

### `PATCH /api/alerts/{id}` 🔒 admin/analyst
Body: `{"status": "resolved"}` or `{"status": "false_positive"}`.
This is the analyst feedback loop — see `docs/architecture.md`.

## Health

### `GET /health`
Basic liveness check, returns `{"status": "ok"}`.
